# HTTP Server, Editor Launcher & Web Dashboard Specs (`WEB`)

## Security & Middleware (`127.0.0.1`)

- [x] **WEB-SEC-001**: When the `repotier` HTTP server starts, the server shall bind strictly to the loopback address `127.0.0.1:<port>`.
- [x] **WEB-SEC-002**: When the `localhostGuard` middleware handles a non-`GET` and non-`HEAD` HTTP request whose `Origin` header is non-empty and does not equal `http://127.0.0.1:<port>` or `http://localhost:<port>`, the server shall reject the request with `403 Forbidden` and JSON body `{"error":"forbidden origin"}`.
- [x] **WEB-API-001**: If any REST API endpoint returns a non-`2xx` and non-`409` error response, then the server shall serialize a JSON error envelope `{"error": "<message>", "git_error": "<optional_git_stderr>"}`.

## REST API Endpoints

- [x] **WEB-API-002**: When `GET /api/health` is requested, the server shall respond with `200 OK` and `{"status":"ok","version":"<version>","pid":<pid>,"port":<port>}`.
- [x] **WEB-API-003**: When `POST /api/shutdown` is requested, the server shall respond with `202 Accepted` (`{"status":"shutting_down"}`) and asynchronously trigger graceful server shutdown.
- [x] **WEB-API-004**: When `GET /api/repos` is requested, the server shall return `200 OK` with all cached repositories (`path`, `name`, `exists`, `last_seen`, and transient `remotes` when `exists == true`) via `STORAGE.ListRepos()`.
- [x] **WEB-API-005**: When `DELETE /api/repos` is requested with `{"path":"<path>"}`, the server shall remove that path from `repos.json`; when requested with `{"prune_missing":true}`, the server shall remove all cached repositories where `exists == false`.
- [x] **WEB-API-006**: When `GET /api/repo/details?path=<encoded_path>` is requested, the server shall return `{"exists":false,"is_local_only":false,"remotes":[],"worktrees":[],"branches":[],"remote_refs":[]}` (`200 OK`) if the repository is unhealthy/missing, or `{"exists":true,"is_local_only":<bool>,"remotes":[...],"worktrees":[...],"branches":[...],"remote_refs":[...]}` populated from `GITOPS` if healthy.
- [x] **WEB-API-013**: When `GET /api/repo/remote-items?path=<encoded_path>[&remote=<name>]` is requested, the server shall return `200 OK` with `{"is_local_only":true,"remote":"","issues":[],"prs":[]}` when the repository has zero remotes, or `{"is_local_only":false,"remote":"<name>","issues":[...],"prs":[...]}` populated via `GITOPS.ListRemoteIssuesAndPRs`.
- [x] **WEB-API-014**: When `POST /api/repo/fetch` is requested with `{"repo_path":"..."}`, the server shall invoke `GITOPS.FetchRepo(repo_path)` and return `200 OK` (`{"status":"ok"}`) on success or `400 Bad Request` with the standard JSON error envelope on failure.
- [x] **WEB-API-015**: When `GET /api/settings/logging` or `PUT /api/settings/logging` is requested, the server shall return or validate/persist `logging` configuration (applying the updated log level and rotation thresholds dynamically without restarting the daemon, or returning `400 Bad Request` on invalid values); when `GET /api/logs?lines=100` is requested, the server shall return the last `N` lines (max `500`) of `~/.cache/repotier/daemon.log`.
- [x] **WEB-API-007**: When `POST /api/branches/upstream` is requested with `{"repo_path":"...","branch":"...","upstream":"..."}`, the server shall invoke `GITOPS.SetBranchUpstream` to set (or unset when `upstream` is `""`) the branch's upstream ref and return `200 OK`.
- [x] **WEB-API-008**: When `DELETE /api/branches` is requested with `{"repo_path":"...","branch":"...","force":<bool>}`, the server shall return `200 OK` (`{"branch_deleted":true}`) on success, `409 Conflict` (`{"branch_deleted":false,"requires_force":true,"git_error":"..."}`) when `GITOPS` returns `ErrNotFullyMerged`, or `400 Bad Request` if the branch is currently checked out in any worktree (`checked_out_in != ""`).
- [x] **WEB-API-009**: When `DELETE /api/worktrees` is requested with `{"repo_path":"...","worktree_path":"...","branch":"...","delete_branch":<bool>,"force":<bool>,"force_worktree":<bool>}`, the server shall remove the linked worktree first and then optionally delete the branch, returning `200 OK` (`{"worktree_removed":true,"branch_deleted":<bool>}`) on full success, `409 Conflict` (`{"worktree_removed":true,"branch_deleted":false,"requires_force":true,"git_error":"..."}`) when worktree removal succeeds but branch deletion fails with `ErrNotFullyMerged`, or `400 Bad Request` on primary/dirty worktree refusal.
- [x] **WEB-API-010**: When `GET /api/editors` is requested, the server shall return all 5 supported editors (`agy`, `vscode`, `windsurf`, `intellij`, `subl`) with `id`, `label`, `detected_path`, `override_path`, and `available`.
- [x] **WEB-API-011**: When `PUT /api/settings/editors` is requested with `{"overrides":{...}}`, the server shall validate and persist the overrides via `STORAGE.SaveEditorOverrides`, returning `200 OK` with updated editor descriptors or `400 Bad Request` if validation fails.
- [x] **WEB-API-012**: When `POST /api/worktrees/open` is requested with `{"editor_id":"...","worktree_path":"..."}`, the server shall resolve an empty or `"~"` `worktree_path` to `os.UserHomeDir()`, verify the target directory exists on disk, resolve and launch the requested editor asynchronously, and return `200 OK` (`{"status":"launched"}`).

## Editor Resolution & Non-Blocking Launch

- [x] **WEB-EDIT-001**: When resolving an editor binary for `agy`, `vscode`, `windsurf`, `intellij`, or `subl`, the editor launcher shall check in priority order: (1) non-empty validated `override_path` from `config.json`, (2) `exec.LookPath` CLI binary names, (3) `Extra Probe Paths` (`~/` expanded), and (4) on `darwin`, `/Applications/<AppName>.app`.
- [x] **WEB-EDIT-002**: When launching a resolved editor target for a worktree path, if `runtime.GOOS == "darwin"` and the resolved path is a directory ending in `.app` (or a macOS `.app` fallback name), the launcher shall invoke `open -a <app> <worktree_path>`; otherwise it shall invoke `<resolved_binary> <worktree_path>`, starting the process with `cmd.Start()` and reaping it in a background goroutine (`cmd.Wait()`).

## Embedded Frontend Dashboard (`ui/index.html`)

- [x] **WEB-UI-001**: The `repotier` binary shall embed `ui/index.html` via `//go:embed` and serve it at `GET /` with zero external runtime or CDN asset dependencies.
- [x] **WEB-UI-002**: When the dashboard loads in the browser, the top navigation repository dropdown shall list only cached repositories with `exists == true`; if `?repo=<path>` references a missing or unreachable repository (`exists == false`), the UI shall display a dismissible warning banner (*"Repository folder is no longer present or reachable"*) and select the first available valid repository (or render the empty-state onboarding view if no valid repositories exist).
- [x] **WEB-UI-003**: When the browser window gains focus (`window.focus`) or becomes visible (`visibilitychange` to `visible`), or when the user clicks the manual Refresh button, the dashboard shall silently re-fetch `/api/repos` and `/api/repo/details` for the active repository.
- [x] **WEB-UI-004**: In the Workspace tab's Worktrees section, the dashboard shall render each worktree's path, branch/detached badge, `Main` badge (for `is_main: true`), dirty count badge, an `"Open in ▾"` editor dropdown (with unavailable editors disabled and linked to Settings), and a `"Remove"` button that is hidden or disabled on the primary worktree (`is_main: true`).
- [x] **WEB-UI-005**: When the user opens the Worktree Removal confirmation modal (`is_main: false`), the UI shall provide checkboxes for `Also delete local branch (<branch>)`, `Force delete unmerged branch (-D)` (enabled when branch deletion is checked), and `Force remove worktree (--force)` (highlighted when `dirty_count > 0`), and if `DELETE /api/worktrees` returns `409 Conflict` (`requires_force: true`), update the modal inline with `git_error` and a **"Force Delete Branch (-D)"** retry button.
- [x] **WEB-UI-006**: In the Workspace tab's Local Branches section, the dashboard shall render each branch's name, upstream combobox (populated with `remote_refs` plus an `"Unset upstream"` option that saves immediately via `POST /api/branches/upstream`), ahead/behind/gone badge, checked-out worktree path, and a Delete action that is disabled with tooltip *"Checked out in main repository directory"* when `is_main_wt == true`, opens the Worktree Removal Modal with `Also delete local branch` pre-checked (`DELETE /api/worktrees`) when checked out in a linked worktree (`checked_out_in != ""` and `is_main_wt == false`), and supports `-D` force escalation on `409 Conflict` (`DELETE /api/branches`) for unattached branches.
- [x] **WEB-UI-007**: In the Settings tab, the dashboard shall render (1) the Cached Repositories table showing `Active`/`Unreachable` status badges, `last_seen`, per-row Remove, and bulk **Prune Unreachable** (updating active repo selection and URL via `history.replaceState` if the active repo is removed), (2) the Editor Binary Overrides table with detected path, editable override input, **Save**, and **Test Launch**, and (3) Daemon Info showing version, PID, `127.0.0.1:<port>`, and a **Shutdown Daemon** button.
- [x] **WEB-UI-008**: At the top of the Workspace tab, the dashboard shall render a Remotes bar listing each configured Git remote (`name` and clickable `web_url`) when the repository has remotes, or a Local-Only Repository banner (*"This repository is local-only (no Git remotes configured)"*) when `is_local_only == true`.
- [x] **WEB-UI-009**: In the Repositories tab (`Workspace` | `Repositories` | `Settings`), the top navigation dropdown shall present all unique canonical remote repositories across all active cached workspaces (labeled without remote-alias prefixes) and default-select the originating workspace's `origin` remote repository, else its first remote's repository, else a disabled `local-repo` anchor option (showing the local-only banner and hiding Issues/PRs); selecting any remote repository shall list all matching local clones and their worktrees in **Workspaces** (including a **Remote** column showing each clone's remote name(s)) and fetch read-only **Issues** and **Pull Requests**; switching back to the **Workspace** tab shall return to the originating workspace if the repository was not changed (including staying on `local-repo`), switch to the first workspace in the clone list if the repository was changed, or jump to the clicked clone/worktree on **View in Workspace**.
- [x] **WEB-UI-010**: In the Workspace tab's Local Branches section, the dashboard shall provide a **Fetch** button (disabled when `is_local_only == true`) paired with an info hover card explaining that it runs `git fetch --all --prune` to refresh remote tracking deltas and prune deleted upstream branches, calling `POST /api/repo/fetch` and re-fetching `/api/repo/details` on completion.
- [x] **WEB-UI-011**: In the Settings tab, the dashboard shall render a **Daemon Logging** section showing `log_path`, **Log Level** (`debug`, `info`, `warn`, `error`), **Max Size (MB)**, **Max Backups**, a **Save** button (`PUT /api/settings/logging`), and a **View Last 100 Lines** button opening a log viewer modal (`GET /api/logs?lines=100`).
- [x] **WEB-UI-012**: When user actions (`Fetch`, `Save`, `Open in`, `Remove`, `Prune`, `Upstream`, `Shutdown`) succeed or fail in the dashboard, the UI shall display a stacked auto-dismissing toast banner (`4s` timeout, max `4` visible) and record the timestamped event in an in-memory Activity Hub (capped at `100` entries since page launch) accessible from a top-nav bell icon button whose count badge is hidden when `0` and includes a Clear action.
- [x] **WEB-UI-013**: In the top navigation bar, the dashboard shall provide a theme selector supporting **Midnight Slate** (default dark), **Rosé Pine** (dark rose), **Rosé Pine Dawn** (light rose), **Solarized Dark**, **Solarized Light** (light gold), **Sky Light** (light sky blue), and **Zinc Light** (light grey) palettes via CSS custom properties, persisted across reloads in `localStorage`.
